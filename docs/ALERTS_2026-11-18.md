# Alerts (18 November 2026)

The owner asked for "one more good feature in the floor that makes it Bloomberg like" and chose **alerts**, Bloomberg's
ALRT: set an alert, and the moment it is hit you are told.

## What can be watched

| Alert | Hit when | Afterwards |
|---|---|---|
| Price at or above | the share's last price reaches it | spent |
| Price at or below | the share's last price falls to it | spent |
| A day's move | the share is up or down at least that much (0.5% to 50%) from yesterday's close | at most once a trading day; stays set |
| News | each new story naming the company, as its day comes | stays set |
| Flash storm | each storm on the Floor as it starts | stays set |
| Wealth client | each new client looking for a manager | stays set |

A player keeps at most 20 alerts set and cannot set the same one twice. Each may carry a note to themselves (up to 80
characters), shown when it is hit. A price alert set where the share already is says so, and is hit at once. News,
storm and client alerts never fire for anything from before they were set.

## Where

- **The Trading floor**, an "Alerts" panel: what was hit (newest first, the unseen in bold), "Mark as seen", the form to set
  one, and those set with "Remove". It refreshes the moment an alert is hit.
- **The terminal's command line:** `ALERT HMB > 9.50` (or `ABOVE`), `ALERT HMB < 8` (or `BELOW`), `ALERT HMB MOVE 5`,
  `ALERT HMB NEWS`, `ALERT STORM`, `ALERT WEALTH`, and `ALERTS` to open the Trading floor. Hints appear as you type `AL`.
- **"Needs you now"** on the desk: "2 alerts have been hit" until they are seen.

## How it works

The server looks at every alert set every few seconds, in the same loop as the market (a fault there never holds the
market up). Nothing here touches money, and an alert never shows anything its player could not already see.

**Website.** `GET /api/alerts`; `POST /api/alerts` (`{kind, ticker, level, note}`; level in kobo for a price, in
hundredths of a percent for a move), `/api/alerts/remove` (`{alert_id}`), `/api/alerts/seen`. `GET /api/me` carries
`alerts_unseen`. Migration `071_alerts.sql`; code `simulation/alerts.py`, `server/alert_routes.py`, `web/src/FloorAlerts.tsx`.

**Tests.** `tests/test_alerts.py` (5): a price alert hit once then spent and waiting unseen; a move alert at most once a day;
news, storm and client alerts for each new one only; the refusals (unknown share, bad level, repeats, more than twenty, someone
else's alert); the routes. `command.test.ts` reads every form of `ALERT`.
